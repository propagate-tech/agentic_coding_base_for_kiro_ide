# setup skill

## このスキルが目指すゴール

受講者が「セットアップして」の一言で、

1. 自分の持ち込みPC（mac / Windows）に合った Node.js ポータブル版が
2. `runtime/node/` に展開され
3. `runtime/node/bin/node`（mac）/ `runtime\node\node.exe`（Windows）から実行できる

状態になること。

**受講者がターミナルコマンドを自分で打つ必要をなくす**のが最大の狙い。コマンドはすべてこの skill が代行し、受講者には「画面のどこを見て何を答えればいいか」だけを案内する。

## 起動トリガー (発動キーワード例)

以下のような依頼が来たら、迷わずこの skill を発動する:

- 「セットアップして」「環境構築して」「初期設定して」
- 「Node を用意して」「Node.js をインストールして」
- 「最初に何すればいい?」「まず何から?」（ハンズオン開始直後の文脈）
- 「node が動かない」「node コマンドが無いと言われた」

## 想定ユーザー

- ビジネスパーソン、または初学者エンジニア
- 「自分のPCが Mac か Windows かは分かるが、バージョンや CPU の種類は分からない」人
- ターミナルでコマンドを打つのに強い不安がある人

そのため:

- **専門用語の初出時はカッコ書きで補足**する。例:
  - 「アーキテクチャ (CPU の種類。Apple Silicon か Intel か、など)」
  - 「アーカイブ (複数ファイルを1つにまとめた圧縮ファイル)」
- コマンドの中身を説明しすぎない。**「今これをやっています」「これで完了です」**と結果を伝えることを優先する。

## 全体の流れ

```
1. OS を確認（mac か Windows か）
2. OSバージョン・CPU（アーキ）を「確認方法アナウンス付き」でヒアリング
3. 要件を満たすか判定（満たさない場合は正直に伝える）
4. 該当アーカイブを runtime/node/ に展開
5. フルパスで node -v を実行して動作確認
6. 完了報告
```

**必ずこの順で進める。特に 2 の「ヒアリング」を飛ばして展開に進んではいけない。**

---

## ステップ1: OS を確認する

まず受講者に、Mac か Windows かを尋ねる。自動判定を試みてもよいが（後述）、最終的には受講者の回答を正とする。

> 「まず、お使いのPCは **Mac** ですか、**Windows** ですか?」

（任意）ターミナルで判定できる場合は補助的に使う。`uname` が通れば mac/Linux 系、通らなければ Windows の可能性が高い。ただし**判定結果を鵜呑みにせず、受講者への確認を優先**する。

---

## ステップ2: OSバージョンと CPU をヒアリングする（最重要）

OS が分かったら、**確認方法をそのまま案内した上で**、バージョンと CPU（アーキテクチャ）を受講者に答えてもらう。以下の案内文を、そのまま受講者に提示する。

### Mac の場合

> お使いの Mac のバージョンと CPU を確認します。以下の手順で表示された内容を教えてください。
>
> 1. 画面左上の **アップルメニュー（🍎）** をクリック
> 2. 「**このMacについて**」を選択
> 3. 表示されたウィンドウの中の、次の2つを教えてください:
>    - **macOS のバージョン**（例: `macOS Sonoma 14.5`、`macOS Ventura 13.6` など）
>    - **チップ / プロセッサ**（例: `Apple M1`、`Apple M2` → Apple Silicon / `Intel Core i5` → Intel）

### Windows の場合

> お使いの Windows のバージョンと CPU を確認します。以下の手順で表示された内容を教えてください。
>
> 1. **スタートボタン** を右クリック →「**システム**」を選択（または「設定」→「システム」→「バージョン情報」）
> 2. 表示された画面の、次の2つを教えてください:
>    - **エディション / バージョン**（例: `Windows 11 Pro`、`Windows 10 Home` など）
>    - **システムの種類**（例: `64 ビット オペレーティング システム、x64 ベース プロセッサ` → x64 / `ARM ベース プロセッサ` → arm64）

**受講者の回答（バージョン + CPU）が揃うまで、次のステップに進まない。** どちらか欠けていたら、その項目だけ再度たずねる。

---

## ステップ3: 要件を満たすか判定する

ヒアリング結果を、以下の対応表・要件と照らし合わせる。

| OS | CPU（回答の目安） | 使うアーカイブ | 最低OSバージョン |
|---|---|---|---|
| macOS | Apple Silicon（Apple M1/M2/M3…） | `dist/node-v24.18.0-darwin-arm64.tar.gz` | macOS 13.5 以上 |
| macOS | Intel（Intel Core…） | `dist/node-v24.18.0-darwin-x64.tar.gz` | macOS 13.5 以上 |
| Windows | x64（64ビット / x64 ベース） | `dist/node-v24.18.0-win-x64.zip` | Windows 10 / Server 2016 以上 |
| Windows | arm64（ARM ベース） | `dist/node-v24.18.0-win-arm64.zip` | Windows 10 以上 |

判定ルール:

- **バージョンが最低要件を下回る場合**は展開を進めず、正直に伝える。
  - 例（Mac）:「恐れ入ります、この Node.js は macOS 13.5 以上が対象です。お使いのバージョンでは動作保証外のため、講師にご相談ください。」
- **CPU が判別できない回答**（「よく分からない」等）の場合は、ステップ2の確認方法をもう一度案内する。それでも不明なら、講師に相談するよう促す。
- 32bit Windows（`x86 ベース`）など**対応アーカイブが無い環境**の場合も、正直に「同梱版では対応できない」と伝え、講師に相談を促す。

判定できたら、どのアーカイブを使うか一言添えてから展開に進む。

> 「Apple Silicon の Mac ですね。`darwin-arm64` 版を展開します。」

---

## ステップ4: 該当アーカイブを展開する

`runtime/node/` に展開し、フォルダ名を `node` に統一する。**このコマンドは skill が実行する。受講者に打たせない。**

### Mac（Apple Silicon の例。Intel なら `darwin-x64` に読み替え）

```bash
mkdir -p runtime
tar -xzf dist/node-v24.18.0-darwin-arm64.tar.gz -C runtime
mv runtime/node-v24.18.0-darwin-arm64 runtime/node
```

### Windows / PowerShell（x64 の例。ARM なら `win-arm64` に読み替え）

```powershell
New-Item -ItemType Directory -Force -Path runtime | Out-Null
Expand-Archive -Force dist\node-v24.18.0-win-x64.zip -DestinationPath runtime
Rename-Item runtime\node-v24.18.0-win-x64 runtime\node
```

制約:

- 展開先は必ずワークスペース直下の `runtime/`。ホームディレクトリ等には展開しない（全受講者でパスを揃えるため）。
- すでに `runtime/node/` が存在する場合は、まず動作確認（ステップ5）を行い、正常なら再展開せず「すでにセットアップ済み」と伝える。壊れている場合のみ `runtime/node` を削除して展開し直す（削除は必ず受講者に一言断ってから）。
- **PATH は通さない。** 環境変数はいじらない。以降の開発は各 skill が `runtime/node` のフルパスで `node` を呼び出す。

---

## ステップ5: フルパスで動作確認する

展開先の `node` を**フルパスで**実行し、バージョンを確認する。

### Mac

```bash
runtime/node/bin/node -v
```

### Windows / PowerShell

```powershell
runtime\node\node.exe -v
```

`v24.18.0` と表示されれば成功。表示されない・エラーになる場合は、展開先のフォルダ構成（`runtime/node/bin/node` / `runtime\node\node.exe` が存在するか）を確認し、必要なら展開し直す。

---

## ステップ6: 完了を報告する

成功したら、専門用語を避けて簡潔に伝える。

> 「セットアップが完了しました ✅ Node.js v24.18.0 が `runtime/node` に用意できています。以降の作業では、この Node をこちらで自動的に使うので、受講者側で追加の設定は不要です。次は『何か作ってみたいので相談に乗って』と話しかけてみてください。」

## 絶対に守る制約（まとめ）

1. **ヒアリングを飛ばさない。** OSバージョンと CPU を、確認方法の案内付きで必ず受講者から聞く。
2. **要件を満たさない場合は展開しない。** 正直に伝え、講師相談を促す。ごまかして進めない。
3. **展開先は `runtime/node/` に固定。** フォルダ名は `node` に統一する。
4. **PATH・環境変数を変更しない。** 以降は各 skill がフルパスで `node` を呼ぶ。
5. **コマンドは skill が代行する。** 受講者にターミナル入力をさせない。削除を伴う操作は必ず事前に一言断る。
